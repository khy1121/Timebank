# G2 MVP 스코프 — 할 일 이자 (가칭)

소프트 론칭 상한: **6주**. 넘칠 것 같으면 일정이 아니라 범위를 자른다.

## build (3개)
1. **할 일 + 이자 엔진**: 추가(제목·원금·기한), 완료(상환), 기한 초과 시 일 복리 계산, 첫 화면에 총 부채·신용등급
2. **계정 + 동기화**: 이메일 인증 로그인, 서버 저장, 본인 데이터만 접근
3. **이자 알림**: 기한 당일, 이자가 붙기 시작한 날 로컬 알림

이자 규칙 초안(L0 결과로 조정): 원금 1,000~5,000냥(중요도 5단계), 일 10% 복리, 상한 원금의 10배.

## fake / manual
| 항목 | 방식 |
|---|---|
| 피드백 접수 | 앱 안 "의견 보내기" → 메일 앱 열기 (manual) |
| 주간 리포트 | 내가 SQL로 직접 집계 (manual) |

## 제외 + 되살릴 조건
| 항목 | 되살릴 조건 |
|---|---|
| 홈 화면 위젯 | 주간 재방문 사용자 50명 이상 |
| 부채 현황 공유 카드 | 의견 중 "공유하고 싶다" 5건 이상 |
| 반복 할 일 | 같은 요청 5건 이상 |
| 소셜 로그인(구글·애플) | 가입 화면 이탈률 50% 초과 |
| 유료 결제 | 2주차 재방문율 20% 이상 |
| 친구와 부채 비교 | 주간 재방문 사용자 200명 이상 |

## 포기 불가 6항목
- 데이터 유실 방지: 서버 저장 + 오프라인 입력분 재전송
- 인증/권한: 행 단위 보안으로 본인 데이터만
- 결제 정확성: 결제 없음(해당 없음)
- 개인정보 최소화: 이메일만 수집, 처리방침 페이지, 계정 삭제 기능(스토어 심사 요건)
- 에러 로깅: Sentry, 사용자 ID 부착
- 접근성 기본: 글자 크기 대응, 스크린리더 라벨, 색만으로 상태 구분하지 않기

## 스택
- 앱: Expo (React Native, TypeScript) — 안드로이드·iOS 동시
- 백엔드: Supabase (Auth, Postgres, 행 단위 보안)
- 빌드·배포: EAS Build / Submit (윈도우에서 iOS 빌드 가능)
- 에러: Sentry
- 필요 비용: 구글 개발자 등록 25달러(1회), 애플 연 99달러

## G3 계측 (출시 전 구현)
- 이벤트 테이블 `events(user_id, event, ts, props)`
- 활성화 이벤트 1개: **이자가 붙은 할 일을 처음 상환**
- 가입일 + 유입 경로 저장
- 주간 집계 SQL 1개
- 피드백 채널: 매일 보는 메일함
- Sentry에 사용자 ID 부착

## 시리즈 공통화 메모
2번 앱부터 재사용할 것: 로그인, 이벤트 기록, 에러 로깅, 계정 삭제, 처리방침. 단, 1번 앱에서는 미리 공통 모듈로 빼지 않는다. 2번 앱에서 두 번째로 필요해질 때 추출한다.
